## JSX: More Than Just HTML in JavaScript

Remember, JSX is *not* HTML. It's a syntax extension that gets compiled to JavaScript. This means it follows JavaScript rules, not HTML rules.

When you write `<h1 className="title">Hello!</h1>`, it gets compiled to `React.createElement('h1', { className: 'title' }, 'Hello!')`. JSX is just syntactic sugar!

Let's look at the important differences:

### JSX Rule #1: className, not class

In HTML, you'd write `class="title"`. In JSX, you write `className="title"` because `class` is a reserved word in JavaScript.

**Wrong:** `<div class="container">` 
**Correct:** `<div className="container">`

### JSX Rule #2: camelCase Everything

All attributes use camelCase in JSX:

### JSX Rule #3: Self-Closing Tags Must Close

In HTML, some tags don't need closing: `<img>`, `<br>`, `<input>`. In JSX, **all** tags must close.

**HTML style (won't work):** `<img src="cat.jpg">` `<input type="text">` `<br>`
**JSX requires:** `<img src="cat.jpg" />` `<input type="text" />` `<br />`

### JSX Rule #4: One Parent Element Only

JSX expressions must have a single parent element. You can't return sibling elements directly—wrap them in a `<div>` or use a **Fragment** (`<>...</>`) when you don't want an extra DOM element.

> **Pro tip:** Fragments (`<>...</>`) are perfect when you don't want an extra wrapper div cluttering your DOM.

## JavaScript Expressions in JSX

The real power of JSX is mixing JavaScript with your markup. Use curly braces `{}` to embed any JavaScript expression.

For example: `<h1>{greeting}, {name}!</h1>` will evaluate the variables and display their values.

### What Can Go Inside `{}`?

You can use any **expression** (something that produces a value):

- Variables: `{name}`
- Math: `{2 + 2}`
- Object properties: `{user.firstName}`
- Ternary operator: `{isLoggedIn ? 'Hi!' : 'Log in'}`
- Function calls: `{formatDate(new Date())}`
- Array methods: `{items.map(i => i.name)}`

You **cannot** use statements (if, for, let) directly—but ternary operators and map() work great!

## Building Functional Components

A **functional component** is just a JavaScript function that returns JSX. Simple as that!

The simplest component: `function Hello() { return <h1>Hello, World!</h1>; }`
Or as an arrow function: `const Hello = () => <h1>Hello, World!</h1>;`

### Component Rules

1. **Names must start with a capital letter** (React needs to distinguish components from HTML elements)
2. **Must return JSX** (or null)
3. **One root element** (use Fragment if needed)

**Why uppercase?** `<button />` creates an HTML button, but `<Button />` renders your custom Button component. React uses capitalization to tell them apart!

## Props: Passing Data to Components

**Props** (short for properties) let you pass data to components. They're like function parameters for your UI.

Without props, components are hardcoded. With props, you can write `<Greeting name="Sarah" />` and reuse the same component with different data!

### Props Syntax: Destructuring

You can receive props two ways:

- **Props object**: `function Greeting(props) { return <h1>Hello, {props.name}!</h1>; }`
- **Destructuring** (cleaner): `function Greeting({ name }) { return <h1>Hello, {name}!</h1>; }`

Destructuring is preferred because it's cleaner and makes it obvious what props the component expects.

### Default Props

Set default values with JavaScript default parameters: `function Button({ label = 'Click me', color = '#3b82f6' }) { ... }`

If no prop is passed, the default is used!

### Passing Different Types of Props

Props can be any JavaScript value: strings, numbers, booleans, arrays, objects, or even functions. Just wrap non-string values in curly braces: `count={42}` `isActive={true}` `items={['a', 'b']}`

## Rendering Lists with map()

One of the most common patterns in React is rendering a list of items using `array.map()`. Each item gets transformed into JSX!

The pattern: `{items.map(item => <li key={item.id}>{item.name}</li>)}`

### The `key` Prop: Why It Matters

React needs a unique `key` for each list item to efficiently update the DOM:

- **Bad:** No key - React will complain in console
- **Avoid:** Index as key `key={index}` - Works but not ideal (can cause bugs with reordering)
- **Best:** Unique ID as key `key={item.id}` - Best practice!

> **Why unique keys?** They help React identify which items changed, added, or removed. Without them, React might update the wrong elements!

## Conditional Rendering

React gives you several ways to show or hide content based on conditions:

### Method 1: Ternary Operator

Best for toggling between two things:

`{isLoggedIn ? <h1>Welcome back!</h1> : <h1>Please sign in</h1>}`

### Method 2: Logical AND (&&)

Best for showing something OR nothing:

`{count > 0 && <span className="badge">{count}</span>}`

### Method 3: Early Return

Best for hiding entire components. At the top of your function: `if (!user.isAdmin) return null;`

## Composing Components

The real power of React is **composition** - building complex UIs from simple components.

The pattern: Create small, focused components (`Avatar`, `UserInfo`), then compose them into bigger ones (`UserCard`), which combine into pages (`TeamList`). Each piece is reusable and testable!

### The Children Prop

The special `children` prop lets you pass components as content. Anything between opening and closing tags becomes `children`:

```jsx
<Card title="Welcome">
  <p>This paragraph is passed as children!</p>
</Card>
```

Inside Card, you access it via `{children}` and render it wherever you want.

    }
  ]}
