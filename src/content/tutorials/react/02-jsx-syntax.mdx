# JSX Syntax: Writing HTML in JavaScript

JSX is React's superpower - it lets you write HTML-like code right inside JavaScript. But it's not exactly HTML, and learning the differences will save you hours of debugging. Let's master it! 🚀

## What You'll Learn

- The core JSX syntax rules (and why they exist)
- How to embed JavaScript expressions in JSX
- Dynamic styling and attributes
- Fragments and when to use them

## JSX Rules: The Non-Negotiables

JSX looks like HTML, but it's actually JavaScript. This means a few rules are different:

### Rule 1: Use className, Not class

```jsx
// ❌ Won't work - class is a reserved JavaScript keyword
<div class="container">

// ✅ Use className instead
<div className="container">
```

### Rule 2: camelCase for Attributes

All multi-word attributes use camelCase:

### Rule 3: Self-Closing Tags

Every tag without children MUST self-close:

```jsx
// ❌ This will cause an error
<img src="photo.jpg">
<input type="text">
<br>

// ✅ Self-close all void elements
<img src="photo.jpg" />
<input type="text" />
<br />
```

### Rule 4: One Root Element

JSX expressions must have a single parent element:

```jsx
// ❌ Multiple root elements - won't work
return (
  <h1>Title</h1>
  <p>Paragraph</p>
);

// ✅ Wrap in a single parent
return (
  <div>
    <h1>Title</h1>
    <p>Paragraph</p>
  </div>
);

// ✅ Or use a Fragment (no extra div!)
return (
  <>
    <h1>Title</h1>
    <p>Paragraph</p>
  </>
);
```

## Fragments: The Invisible Wrapper

When you need to return multiple elements but don't want an extra `<div>`, use a Fragment:

```jsx
// Fragment syntax - no extra DOM node
<>
  <Header />
  <Main />
  <Footer />
</>

// Or with explicit Fragment (when you need a key)
<React.Fragment key={id}>
  <Header />
  <Main />
</React.Fragment>
```

Fragments are perfect for:
- Lists where you can't add a wrapper
- Component returns that shouldn't add DOM nodes
- Keeping your HTML structure clean

## Dynamic Styles

JSX uses JavaScript objects for inline styles. Property names are camelCase:

```jsx
// CSS property → JavaScript object property
// background-color → backgroundColor
// font-size → fontSize
// padding-top → paddingTop

<div style={{
  backgroundColor: '#3b82f6',
  fontSize: '16px',
  paddingTop: '20px'
}}>
```

## Comments in JSX

Comments inside JSX need curly braces:

```jsx
return (
  <div>
    {/* This is a JSX comment */}
    <h1>Hello</h1>
    
    {/* 
      Multi-line comments
      work the same way
    */}
    <p>World</p>
  </div>
);
```

## Common JSX Gotchas

Watch out for these common mistakes:

<ComparisonTable
  headers={['❌ Mistake', '✅ Correct', 'Why']}
  rows={[
    {
      label: '{if (x) return <A />}',
      values: ['{x ? <A /> : null}', "Statements don't work, use expressions"],
      highlighted: true
    },
    {
      label: 'style="color: red"',
      values: ['style={{ color: "red" }}', 'Must be an object'],
    },
    {
      label: 'class="btn"',
      values: ['className="btn"', 'class is reserved in JS'],
    },
    {
      label: '<input type="text">',
      values: ['<input type="text" />',  'Must self-close'],
      highlighted: true
    },
    {
      label: '{/* comment */}',
      values: ['{/* comment */}', 'Comments need braces inside JSX ✓'],
    }
  ]}
  caption="Common JSX mistakes and how to fix them"
/>

> **Key Insight:** Inside curly braces, you can use any JavaScript **expression** (something that produces a value), but not **statements** (if, for, while). Use ternaries and array methods instead!
